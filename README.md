# Quant Crypto Sniper

> BTC·ETH 현물 추세추종과 위험관리를 위한 24/7 암호자산 자동매매 프로젝트

`quant-crypto-sniper`는 원화 현물 시장에서 큰 추세만 선별하고, 조건이 불명확할 때는 현금을 유지하는 자동매매 시스템을 목표로 합니다. 높은 승률이나 단기 수익을 보장하지 않으며 생존과 손실 제한을 우선합니다.

## 현재 상태

초기 설계 및 전략 코어 단계입니다. **거래소 주문 기능은 아직 구현하거나 활성화하지 않았습니다.** 현재 코드는 완결된 캔들만 사용하는 순수 전략 함수와 포지션 크기 계산, 단위 테스트만 포함합니다.

## 기본 정책

- 대상: `KRW-BTC`, `KRW-ETH` 현물
- 상태: `롱 / 현금`만 사용
- 일봉 100일 이동평균선과 5일 기울기로 상승 국면 확인
- 완결된 4시간봉의 30구간 고점 돌파로 진입 확인
- ATR(14) × 2 초기 손절
- 총 투자 한도 30%, 코인별 최대 15%
- 거래당 계획 손실은 계좌 평가액의 0.5% 이내
- 계좌 고점 대비 10% 손실 시 신규 주문 중단 예정
- 선물, 레버리지, 숏, 물타기, 그리드 매매 제외

## 안전 원칙

- API Key에는 자산조회·주문조회·주문 권한만 사용하고 출금 권한은 부여하지 않음
- API Key와 Secret은 `.env`에만 저장하고 Git에 커밋하지 않음
- 주문 접수가 아닌 실제 체결을 확인한 후 로컬 장부에 반영
- 거래소 잔고와 로컬 상태가 다르면 신규 주문 차단
- 오래되거나 불완전한 캔들로 주문하지 않음
- 24시간 운영 중 장애가 발생하면 재시도보다 주문 차단을 우선

## 예정 구조

```text
거래소 Public REST/WebSocket ─> 캔들 확정 ─> 추세 신호 ─> 위험 한도
                                                              │
거래소 Private API <──────── 체결 확인 <──────── 주문 <────────┘
          │
          └─> 잔고 대조 · 거래 장부 · 상태 대시보드
```

## 로컬 검증

Python 3.10 이상이 필요합니다.

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q quant_crypto_sniper tests
```

## 향후 구현 순서

1. 업비트 공개 캔들 수집기
2. 최근 3~5년 BTC·ETH 비용 포함 백테스트
3. 거래소 인증·잔고 및 주문 가능 정보 조회
4. 고유 주문 식별자와 실제 체결 대조
5. 상태 저장·킬스위치·대시보드
6. 최소 금액 실전 파일럿

## 공개 운영 대시보드

운영 대시보드는 [`dashboard` 브랜치](https://github.com/rundevelrun/quant-crypto-sniper/tree/dashboard)의 `README.md`를 첫 화면으로 사용합니다. 현재는 주문 기능이 연결되지 않은 초기 상태이며, 실시간 수집기 구현 후 다음 정책으로 갱신할 예정입니다.

- 매수·매도·신호 변화·위험·오류 발생 시 즉시 갱신
- 변화가 없어도 매시 00분 10초와 30분 10초에 heartbeat 갱신
- 최근 매수·매도·스킵·위험·오류 이벤트는 3일만 유지
- 현재 포지션과 누적 성과는 기간 제한 없이 표시
- `dashboard` 브랜치는 부모 없는 단일 스냅샷 커밋으로 교체해 Git 이력을 누적하지 않음
- 외부 감시 도구는 `dashboard_state.json`을 읽고, 사람은 브랜치의 `README.md`를 확인

### 공개 항목

- 봇 상태, REST·WebSocket 연결과 데이터 신선도
- BTC·ETH 현재가, 24시간 등락률, 일봉 추세와 4시간봉 돌파 상태
- 매수·보유·현금·청산 신호와 신호 차단 사유
- 포지션 유무, 투자 비중, 수익률과 손절선까지의 거리
- 총 투자 비중, 계좌 낙폭과 킬스위치 상태
- 최근 3일 이벤트와 전략별 누적 성과

### 비공개 항목

- 정확한 총자산과 원화 잔고
- 정확한 코인 수량
- Access Key, Secret Key, JWT와 주문 인증값
- 계정 식별정보와 API 허용 IP

대시보드 생성기는 명시적인 공개 허용목록만 직렬화하며, 알 수 없는 필드는 기본적으로 버립니다.

## 책임과 한계

암호자산은 급격한 가격 변동, 거래소 장애, 유동성 부족과 규제 변화로 큰 손실이 발생할 수 있습니다. 이 저장소는 투자 권유나 수익 보장이 아니며, 실제 운용 책임과 손익은 전적으로 사용자에게 있습니다.
